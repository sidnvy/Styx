# 会话、连接与长期任务的边界

2026-10-19：架构与当前实现核对。服务自动恢复不等于任务可以跨连接、跨执行器重启继续执行。

| 对象 | 所有者与身份 | 当前生命周期 | 验收边界 |
| --- | --- | --- | --- |
| MCP HTTP session | Gateway 分配的认证会话 owner | 没有会话数量上限；新 initialize 时清理默认 15 分钟空闲会话，保护 in-flight 请求及持有 Exec 工作的 owner | 不是稳定聊天账号或任务身份；新连接不可借用旧执行句柄/元素引用 |
| Exec session_id | owner + 设备 ID + generation + 原生执行器会话 | 命令结束且输出排空后释放；write_stdin 检查原 owner 和执行器绑定；失联不重放命令 | Gateway 重启后句柄不持久恢复；新的 MCP 会话不能自动接管旧工作 |
| Cua 连接与上下文 | 设备共享传输；各 owner 单独上下文与引用归属 | 操作短暂排队；活跃和排队操作保护连接，默认 5 分钟空闲后可释放；App/Cua 代次变化使旧引用失效 | 连接重建不恢复旧快照；未知结果的点击、输入不自动重放 |
| Host/Gateway 网络连接 | 持久设备身份、已批准能力、现有凭据 | 断网后重新认证连接，不重建身份或重新配对；撤销后旧凭据拒绝 | 不代表聊天账号已关联，也不代表命令/GUI 已通过真实验收 |
| 长期自主任务 | 应由持久任务 ID 和显式授权管理 | 尚无完整产品实现 | CAS 为受限、无执行副作用实验，不能替代生产任务管理 |

## 资源限制的现状

`0e68ca5` 删除 MCP HTTP maxSessions 及数量拒绝 503 分支。本重构已合并该修复，
不把硬上限调高或转移到其他连接入口。重启服务和本地 initialize 成功不能代替会话积累回归。

当前仍有其他限制，不能宣称“所有 session 都无限制”：

- ExecAdapter 默认最多 64 个保留句柄，包括正在运行、等待输出或不确定的工作。
- 每个 ExecAdapter 生命周期保留最多 100,000 个已分配数字 ID，防止旧句柄与重用 ID 混淆；
  累计上限也会最终拒绝新命令。这是需要单独审查的长期运行边界，不是已完成的长期任务设计。
- Cua 默认最多 64 个等待操作，限制实际桌面争用；不限制 MCP 聊天连接数量。

资源预算应对应实际资源、明确作用范围、给出可诊断的拒绝原因，并保护现有工作。
现有 Exec 预算并非完整的按账号/设备公平调度，也没有完整的产品设置和容量监控。
本轮没有以修复 HTTP 连接故障为由隐式修改 Exec/Cua 调度策略。

## 长期自主任务需要补充的实现

任务记录必须独立于 MCP 连接：至少持久保存目标、状态、授权设备与能力、预算与截止时间、
检查点、执行回执、等待原因和恢复决定。任务应支持待执行、运行、等待用户/权限/网络、
暂停、结果不确定、完成、失败与取消等可审查状态。App/CLI 应使用同一个 Core 管理接口。

再次唤醒任务时，需重新验证用户授权、设备身份与能力、执行器代次和环境现状。
已提交但未取得确定结果的命令或 GUI 操作必须先对账；重连或换一个模型回合不是重放许可。
桌面任务还必须确认交互会话、权限以及当前快照；用户注销后不可宣称继续操作桌面。

后台进程不能自行保证聊天模型持续推理。无人对话时继续任务，还依赖聊天平台支持的模型
唤醒/调度入口及其授权、成本与可用性。若平台没有该能力，只能等待用户在聊天中继续，
不能承诺 App 常驻即可让任意 ChatGPT 会话永久自主执行。

后续验收必须包含：客户端未 DELETE 的会话积累；长 Exec 等待超过空闲回收时间；
客户端重连、Gateway/Host 崩溃、网络中断；旧句柄拒绝与结果不确定处理；多 owner 桌面排队；
任务暂停/取消/预算耗尽、模型未被唤醒，以及撤销授权后禁止继续执行。
这些任务级能力尚未由本次 onboarding 安装包提供或验收。
