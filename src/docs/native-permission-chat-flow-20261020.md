## Resulting user flow

1. Allow Computer Use: each Allow action requests only the matching macOS permission. The App does not simultaneously deep-link to Settings. After a request, a separate Open System Settings action can open that pane without requesting permission again. Process-local request history never counts as a grant; AX and Screen Recording remain independent OS observations.
2. Prepare the secure channel: save the platform Tunnel ID and runtime key once. Save and connect starts the authorized App-owned Tunnel. A retry button is available when configured but not started. Channel readiness is distinct from ChatGPT account verification.
3. Connect in ChatGPT: the default flow uses Add custom MCP server → Tunnel → Create as a plugin → install. No mandatory local create/reuse picker or duplicate presentation form. Existing plugins can be checked in ChatGPT without creating another one.
4. Optional custom package: edit name, description and plugin icon, then Save and export ZIP. The actual Core export route is used through the owning App's authenticated session and CSRF. The package includes presentation, the Tunnel reference and onboarding skill; it contains no runtime key or Gateway bearer credential. It does not change the macOS App icon or automatically synchronize with ChatGPT. Existing reuse profiles remain on their existing management path.
5. Confirm installation, then verify real target-chat calls. User confirmation, archive generation, successful saving, account installation and tool-call acceptance remain separate observations. ZIP import is explicitly a preview path pending target-account compatibility validation.

Saved custom profiles are not replaced by the direct path. Entering the optional editor fills a missing icon only in an unsaved draft. A changed connection context requires an explicit review before preserving presentation/selection in a newly bound local receipt; previous account/export receipts become invalid. No identity or credential is regenerated by this action.
