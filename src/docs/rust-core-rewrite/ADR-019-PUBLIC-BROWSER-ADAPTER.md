# ADR-019 — existing public Browser adapter completion

Status: implementation in progress; actual DOM/HTTP/files acceptance pending. This extends the already integrated three-tool slice to the same frozen 24 Browser names, with no new public schema, backend, policy ledger or inference client.

The Gateway strips only the validated routing field and passes arguments through the existing BrowserAction and pinned native JSON Schema validator. Core retains owner/grant/operation authority; Host retains provider lifetime and cleanup. Unknown actions are not resubmitted. Explicit close after a public Unknown remains unsupported in this slice; authenticated owner cleanup is separate and must preserve the original action history.

The frozen explicit time wait permits thirty seconds; native text/textGone waits retain the pinned backend's action timeout rather than inheriting that time limit. Only browser_wait_for gets a bounded 35-second Host admission/provider budget and 40-second Gateway response wait, with a larger bounded private-wire watchdog. Other public Browser calls retain the existing five-second response bound; Exec and owner cleanup budgets remain unchanged. Timeouts continue to mean Unknown when dispatch may have occurred. No automatic retry is introduced.

File access retains the existing Rust provider's controlled-root policy. Relative filename writes resolve under the original owner's private output directory; absolute filenames must remain in that directory. Existing destinations, symlinks and escapes are refused. Upload/drop reads may use the configured shared workspace or that same owner's output. A shared workspace is not a tenant sandbox. This is intentionally narrower than the frozen upstream schema description saying relative filenames resolve under workspace: do not claim identical file semantics, arbitrary workspace output writes, cross-owner private-output access or remote artifact transfer. A returned path is local to the Host. The original JS provider also configured a per-owner outputDir, but this alone does not prove identical behavior for every upstream filename form.

Reference invalidation follows a trusted local link boundary, independent of network-provided IDs. It must fence both old target resolution and late snapshot results without replacing the context, cookies or executor. Tests of a local port are not ordinary WSS reconnection acceptance. The Gateway still retains the original physical Entry in a binding and has no authenticated same-owner resource-rebind path after WSS replacement. Reference invalidation alone therefore does not establish that a fresh public snapshot can use the old context across reconnection. Do not replace that context or replay its old action to disguise this gap. Inline result/frame bounds remain; small inline PNG and filename outputs need separate real evidence. Unsupported large payloads must remain explicit rather than silently dropping content.

Actual acceptance uses one ordinary paired CLI/MCP journey with independent DOM/HTTP/file/process effects and negative controls, followed by real cleanup. Tool inventory and schema assertions prove routing consistency only. Browser-only Host bootstrap, headed/attach modes, persistent-login migration, Desktop/Cua, packaging and account acceptance remain separate requirements.
