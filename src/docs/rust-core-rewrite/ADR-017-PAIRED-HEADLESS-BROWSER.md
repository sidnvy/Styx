# ADR-017 — ordinary paired headless Browser composition

Status: implementation in progress; native paired acceptance required before integration. This fills an existing rewrite requirement, without changing PUBLIC-MCP-V1 or adding tools.

Gateway retains authentication, routing and owner scopes. One authenticated WSS transport carries Exec and an explicitly negotiated `browser_headless_v1` private feature. The Core enrollment service issues a separate Browser `ConnectionLease` only from the actual approved Browser grant. Browser admission is checked before enqueue, at native transport send and at result delivery. Exec online/Browser feature metadata alone grants nothing. Owner-control messages may use either currently authorized connection lane; Browser business calls never fall back to Exec authorization. The initial physical endpoint remains the existing Exec endpoint: this slice does not claim independent Browser-only Host bootstrap. Device capability CAS retains its all-lanes-offline rule.

Host uses the existing sole Core owner/grant/operation ledger, Browser provider, reserved Host byte budget, supervision, retention and physical cleanup. Private wire calls keep prepare separate from dispatch. References are owner-, operation-, digest- and capability-kind-bound. Repeated dispatch or inspection exposes existing state, never replays a native action or manufactures its prior result. A response timeout/drop remains unknown until original evidence settles it; it does not open another context. Owner revoke fences new work and delivery, while supervised cleanup retains original resources.

Foreground bootstrap reads the original protected profile and publisher-verified release. Only explicit matching local headless selection with `persistLogin=false` is supported here. Node and dependencies come from the retained verified release; the thin worker/config are fixed bytes embedded in this Rust image and staged into a new private namespace. They are not claimed as legacy-signed members. The explicitly selected local Browser executable has a separate local byte/identity check, without a claim that the legacy publisher signed Chrome. Original releases, identity, pairing, publisher pins, permission subjects and login profiles remain unchanged. Unsupported/missing Browser input disables Browser and leaves Exec independent. No original JS Host/Gateway/management supervisor is executed.

Every owner gets fresh private profile/output directories. Presentation mappings are bounded and are not a second authority. Input validation uses bounded tracked blocking jobs; dropping a connection waiter does not abandon an executing validation job. Explicit Host shutdown drains these jobs, and the foreground owner keeps verified inputs and its execution lease until original Node/Browser descendants are physically settled. A Close acknowledgement alone is not cleanup evidence.

The first public integration serves existing navigate/evaluate/close contracts. Other Browser tools retain explicit unsupported behavior. Headed mode, attach, persistent login migration, Linux desktop authorization, Cua batch schemas and performance tuning are outside this slice. No extra model or inference client is introduced.

Required evidence is one ordinary CLI Gateway/Host/pairing/official-MCP journey with independent HTTP effects: navigate nonce, evaluate effect once, owner isolation, sequential private-profile isolation, owner revoke with another owner's Exec surviving, close/Host stop and actual Node/Chrome process/cgroup cleanup. A deliberately withheld native response must be labeled as that fault, never as a WSS-loss test. Grant/local-policy negatives must preserve Exec. Unit or mock results cannot stand in for this journey, cross-platform Browser, accounts, packaging, migration or installed-service acceptance.
