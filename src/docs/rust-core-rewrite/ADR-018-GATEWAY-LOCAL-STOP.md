# ADR-018 — Gateway local stop and remote cleanup uncertainty

Status: implemented, verification pending. Restores C04/C05/C07 lifetime separation; no new execution authority or product scope.

An ordinary paired Browser journey on f17bdb3 reached independent HTTP effects, owner/profile isolation, continued Exec after another owner was revoked, and late-response no-replay. Host cleanup completed, but Gateway Quit waited indefinitely. HTTP shutdown had conflated a retained remote owner cleanup result with a still-running local lifecycle job. The cleanup job had returned Unknown and was not being retried, so waiting did not create new evidence.

Gateway shutdown must join its owned connections, blocking jobs, lifecycle jobs and actual official LocalSessionWorker transports. An attempted-but-unconfirmed local transport is not treated as absent. Shutdown fences further cleanup-job registration under the same synchronous supervisor gate, preventing a late SDK Drop from creating new work after the final local quiescence observation. A job that terminated with a panic is joined but leaves a separate sticky failure flag. The SDK's unavailable detached-task join remains `None`.

Remote owner cleanup is a distinct result. `unconfirmed_owner_cleanups` remains nonzero when completion is unproved. It neither becomes Complete nor authorizes a replay. Daily per-session Closing/retention rules remain unchanged. The original Host Core retains its own operations, native processes and cleanup obligations. On a later authenticated Gateway process epoch, the existing Host epoch transition fences old owner scopes; it does not adopt or replay old operations.

The foreground outcome adds `mcp_session_transports_joined` and `unconfirmed_owner_cleanups`. `local_stop_complete()` requires the actual local joins. `is_complete()` additionally requires confirmed remote cleanup and no worker/listener failure. CLI exit0 still means complete normal shutdown. Exit4 with `remote_owner_cleanup_unconfirmed` means local stop is proved but remote settlement is unconfirmed, without another local failure. Other failures retain exit2. A local worker/transport still running or unconfirmed continues to hold its original owner; no deadline alone releases it.

Verification must distinguish an official-SDK local-worker contract fixture from native acceptance. The actual scenario uses only a fresh owned Host: one native Exec effect, exact Host PID/birth pause, Gateway Quit with local joins and remote Unknown, same-identity Gateway restart, exact original Host resume and original Codex birth continuity, old owner/session rejection and no old nonce replay, then new owner Exec and normal cleanup. This fault is a paused owned process, not a claim of physical remote power loss. Browser positive/negative journeys are separate; no compilation or mock proves installation, platform permissions or final release acceptance.
