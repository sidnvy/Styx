# ADR-021 — headless Browser stays in the owned process scope

Status: implemented; exact-source local and native acceptance pending. No public tools, dependencies, scope adoption or desktop permission changes.

The ordinary2112 recovery controller stopped before socket injection. Its first role assumptions were insufficient; the later exact kernel association established a real boundary defect: a live Chrome main PID had a different cgroup inode from the held Styx scope, while typed children remained in the original group. Original FAIL receipts and real normal cleanup remain preserved. Earlier cgroup observer PASS proves only sampled identities and the original scope limits/emptiness; it does not prove containment of every native descendant at every instant.

The installed Chrome150.0.7871.186 bytes contain `StartTransientUnit` and the Chromium app scope format. [Chromium upstream](https://raw.githubusercontent.com/chromium/chromium/main/components/dbus/xdg/systemd.cc) creates a user systemd scope containing only its current PID during portal initialization. That mechanism is consistent with the actual split; the tagged150 source was not retrieved and no D-Bus method trace was captured. Do not invent a UseSystemd feature flag or claim the original sampled observer proved a different executable image.

Only the Linux headless native Chrome launch receives an explicit `DBUS_SESSION_BUS_ADDRESS=unix:path=/dev/null`. `/dev/null` is a fixed non-socket endpoint, so this child cannot use that address to reach the user session manager. Keep an explicit address rather than omitting it and inviting session-bus auto-discovery. Node and the Rust/systemd supervisor retain their existing real bus; Chromium sandbox remains enabled. No global bus, user unit, original browser, credential, TCC or profile is changed. This headless path has no desktop portal/keyring integration claim; headed/attach/persistent-login support is not inferred. This is normal-lifecycle isolation, not a sandbox against hostile same-UID code deliberately opening the user bus.

Required verification: same frozen new source passes the local gate and real DOM/HTTP/files scene; the existing exact owned recovery journey must prove current main image/birth and kernel cgroup match before and after one socket shutdown, original context markers retained, stale refs refused, fresh effect once, original Exec continued, and final actual cleanup. Do not adopt or stop the external scope as a shortcut. Cancellation or browser-close ACK alone cannot establish descendant exit.
