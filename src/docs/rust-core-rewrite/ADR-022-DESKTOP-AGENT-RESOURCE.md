# ADR-022 — typed Desktop agent affinity, separate capability admission

Status: Core/runtime contracts and Linux workspace checks passed; actual read-only OS association passed; native Cua/GUI journey pending. This is an internal Core resource distinction, not a public tool/schema, second ledger or permission shortcut.

Exec and Browser target operations intentionally require the original resource capability. A native Cua agent instead serves Window, Capture, Pointer, Keyboard and Accessibility in one fixed graphical session. Globally relaxing capability equality would allow an ordinary resource to masquerade as that agent; mapping every action to one Computer boolean would discard the frozen per-capability policy.

`OperationLedger::prepare_desktop_agent` explicitly marks a resource domain. Its original context must be WindowsRead, carry one SessionBinding, and have no observation token. Dispatch still requires real current admission facts. This method does not register a session, discover a backend, claim Ready or infer OS authorization. Ordinary `prepare` remains exact-capability.

Targeted actions inherit the immutable original domain. Only a DesktopAgent domain can serve another Desktop capability, and only under the same owner incarnation, device and exact session generation. Exec, Browser and other sessions remain excluded. Each action retains its own requested capability, immutable payload, fresh grant/local/descriptor/permission/observation/deadline checks, operation identity and once-only dispatch. Resource access repeats those checks. The native adapter must require this domain in addition to its owner/target/session checks. Revocation, unknown history, physical retention and audit settlement remain unchanged.

WindowCapture with AX or set_value fallback to pointer/keyboard can require multiple capabilities; this domain is not compound authorization. Host composition must check actual required capability facts under its existing admission mutex before handing off any permit. Likewise the native permission metadata cannot turn environment variables or portal reachability into Granted/Ready. Those are separate integration requirements and remain incomplete until actual provider evidence exists.

The owned per-session Rust supervisor is the logical Desktop Session Agent. It holds the verified native association and the original bounded watcher/probe jobs. Cua is its separately owned native backend. This reuses the existing process topology and avoids a registration/Ready dependency on an as-yet unstarted action backend. The supervisor instance is minted only after its owned source exists; a candidate or arbitrary instance label cannot register a session. Each action refreshes the exact original association, with watch invalidation, EOF and overflow fencing rather than implicit retargeting.

Only bounded same-peer Hyprland monitors/clients reads establish WindowsRead. Other native permissions are explicitly Unknown/Unavailable, so aggregate readiness is degraded and input remains refused without owned native observation proof. Paired Computer routing has an independent Core ConnectionLease and distinct resource/action kinds; Exec or Browser authorization cannot stand in for it. A fresh protected profile factory pins only the original signed Cua0.36 member. Native raw-byte credit counts input discarded by the official codec. Arbitrary native screenshot output paths are refused until an owned output port exists. These changes do not claim ten-tool parity or platform acceptance.
