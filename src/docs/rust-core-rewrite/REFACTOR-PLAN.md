# Styx 架构提案：一个 Gateway，多台 Host

2026-11-14。部署组合由所有者确定，见[产品范围](REDUCED-SCOPE.md)。下述模块、同机连接方式与迁移顺序是设计建议。

## 产品形态

每套部署有一个 Gateway、一份 OpenAI Private MCP Tunnel 配置和一组已配对的 Host。桌面安装只问一个问题：加入已有 Gateway，还是由这台电脑承载整个部署的 Gateway？前者启动 Host，后者启动 Gateway 和本机 Host。已有中心服务器的用户在所有桌面上选择加入。Headless Linux 安装走服务器入口，只启动 Gateway。没有在线 Host 时，Gateway 仍可接受配对和报告设备状态。

| 运行环境 | 用户选择 | 启动的角色 | 安装所需的能力 |
| --- | --- | --- | --- |
| macOS、Windows、Linux 桌面 | 加入已有 Gateway | Host only | 本机执行器及相应桌面权限；通过邀请配对 |
| macOS、Windows、Linux 桌面 | 在本机建立 Gateway 并使用本机 | Gateway + Host | 一个 Tunnel、本机 Host，以及其他电脑的配对入口 |
| Headless Linux | 部署中心服务器 | Gateway only | Tunnel、Gateway 和管理 CLI；可在没有图形会话、浏览器与桌面执行器的机器上运行 |

“一个”按部署计算。配对记录指定唯一 Gateway；额外安装一台电脑只需邀请。已有部署换中心是显式运维操作；断线和重开都沿用原绑定。由此无需选主、自动接管或搜索网络上所有 Gateway。

## 模块和状态归属

- **Gateway** 对外终结 MCP 与 Tunnel，持有 Tunnel 凭据、配对注册表、设备授权和当前连接。按设备身份路由调用，把执行结果交还原请求方。在线状态来自当前连接；设备身份和授权跨重启保存。
- **Host** 持有本机设备身份、Gateway 地址和信任绑定，主动建立认证连接，报告本机可用能力。它拥有本机执行句柄、取消和资源清理；Exec、Browser、Computer Use 各自沿用 Codex、Playwright、Cua 的执行语义。远端写入结果未知时保留未知，重连只恢复连接。
- **Rust Core** 以库提供共用的身份、授权和操作规则。配对审批归 Gateway，设备侧持久化与执行归 Host。管理入口调用相应角色；只有 Gateway 管理面提供 Tunnel 设置。Core 的存在不要求第三个常驻服务。
- **桌面 App / Linux 服务 / CLI** 负责把角色组合起来。桌面复用一个应用持有的本地 Rust 运行实例，服务器由现有服务管理器启动 Gateway。CLI 和 GUI 展示角色报告的状态。签名载荷的完整校验归安装和更新。

## 一次调用怎样走

ChatGPT 经 Tunnel 将请求送达 Gateway。Gateway 核对权限和目标设备，将请求投递到该设备已有的 Host 连接；Host 交给对应执行器，将结果沿原路返回。组合模式下，本机也登记为一台 Host，建议先复用现有回环连接和相同协议。切换本机与远端设备只改变目标设备 ID。这保留一种授权、一种设备目录和一种调用路径，同时允许两个角色共处一个 Rust 进程。

单中心的代价应直接呈现给用户：Host-only 桌面退出只令这台设备离线；承载 Gateway 的桌面退出或休眠，整套部署的模型入口都随之离线。其他 Host 保留配对并在中心恢复后重连。对全天可用的部署，中心由 headless Linux 服务持有。

## 怎样迁移

1. 从现有三种启动入口确认每种模式实际创建的角色、打开的配置、启动的 worker。沿用既有设备身份、授权、Runtime 选择和协议。优先复用现有 Gateway/Host 启动代码；模式选择集中在启动入口，角色内部无需按三个平台各写一套产品逻辑。
2. 用两种实际拓扑走通同一条用户路径：无桌面服务器加一台桌面 Host；一台桌面同时承载 Gateway 和本机 Host，再加入另一台桌面。两者都经唯一 Tunnel 选择目标电脑执行命令，检查文件效果落在所选设备。复用已通过的执行器证据，重点验证角色组合。
3. 从正常入口移除失去用途的分支：Host-only 的 Tunnel 配置入口、服务器对本机执行器的启动依赖、同机设备专用的调用分支。逐项以实际调用关系为准。既有部署若使用旧模式，先明确兼容或转移路径，再删除对应读取代码。

仓库指导引用这一份角色矩阵。维护者应能根据“谁拥有这个事实”定位功能：改 Tunnel 找 Gateway，改本机权限找 Host，改首次设置的选项找应用入口。参考分支中的类型和模块拆分，只在能让这些边界更清楚时采用。
