# 三平台候选版的用户验收

安装前核对交付记录中的源码提交、文件名和 SHA-256。Mac、Windows 和 Linux 的产物应来自同一集成提交。构建成功、工程测试通过和真实聊天账号可用是三项不同结果。

## macOS：现有设备升级与添加电脑

1. 退出 Styx 后，用候选 DMG 中的 App 更新原安装。保留原有配置；首次启动应显示原电脑与连接，而不是重新注册。签名检查通过只证明代码身份相同，权限是否保留仍须实机观察。
2. 选择“添加电脑”。只有存在多个可选网络地址时才需要选择；生成后复制邀请到另一台电脑的 Styx。
3. 新电脑选择“加入已有”，选择自己提供的能力，粘贴邀请。核对双方显示的配对码，在主台确认。
4. 在原聊天中明确指定新电脑输出 `styx-pairing-ok`（Mac/Linux 用 `printf`，Windows PowerShell 用 `Write-Output`）；随后分别使用所选 Computer Use 或 Browser Automation 做一次真实观察和操作。没有选择的能力不算验收目标。
5. 关闭邀请后，原链接不能再加入新电脑，已连接电脑仍应可执行任务。撤销测试设备后，旧凭据不得重新连入。

如果准备失败，界面应显示继续准备或撤回；如果关闭邀请失败，必须能再次关闭。不要通过删除身份、重新授权或重新配对来掩盖升级问题。

## Windows：安装程序与日常入口

1. 双击本轮交付的 `StyxSetup.exe`。应立即看到安装窗口及进度，安装后通过开始菜单或桌面的 Styx 快捷方式打开。
2. 先检查窗口出现、状态反馈和错误重试，再走与 Mac 相同的设置或加入流程。使用登录用户的桌面验收 Computer Use；SSH 后台会话的成功不能替代这一步。
3. 再次运行安装程序更新。原设备身份、配对及聊天配置应保留。已有前台 App 需要明确退出并重新打开才加载新版本。
4. 有上一版本时使用安装程序的恢复操作；重新打开后应加载原版本并保留设备状态。记录实际版本与结果。

候选安装器是当前用户范围的开发预览；工程记录必须注明 Authenticode 签名和实际安装窗口验收是否完成。

## Linux：Arch CLI / headless / Hyprland

按 [Linux 首次运行步骤](linux-cli-preview.md#first-local-run-headless-gateway-only) 使用独立私有状态目录。Gateway-only 不应安装或启动 Host、Exec、Cua，也不应要求桌面权限。

Host-only 通过邀请加入已有 Gateway，不创建第二个 Gateway。分别执行真实命令，并使用已经安装的 Chrome 或 Edge 做网页观察、输入与点击。浏览器使用独立资料目录；保留登录需要用户完成一次登录。Linux 使用 CLI 管理，不提供桌面 App。

首轮支持 Hyprland 会话中的 Computer Use。选择该能力后，在当前已登录、可交互的 Hyprland 桌面上，通过 Styx 观察一个专用测试窗口，读取截图或界面元素，再执行一次无害操作并核对结果。仅启动驱动或检查版本不算桌面验收。

没有图形会话的 headless 环境不应启动 Cua，也不能显示 Computer Use 就绪；Exec 和 headless Browser Automation 应仍可工作。分别记录无 GUI 隔离环境、实际注销后重新登录、整机重启后的结果；前一项通过不代替后两项。

## 最后共同检查

- 关闭设置窗口后仍可工作；明确退出、服务崩溃和网络中断后，状态与恢复结果应可见。
- 机器重启、登录和再次运行后的身份与配对保持一致；未进入图形会话时不能显示桌面能力就绪。
- 在实际目标 ChatGPT 账号发起工具调用并看到结果，才记为账号验收通过。本机 MCP 探针或工程脚本不代替账号验收。

每次失败记录平台、产物版本、操作到哪一步、实际提示和时间。自动化、原生交互、系统重启与聊天账号的结果分别记录；尚未执行的项目保持“未验收”。
